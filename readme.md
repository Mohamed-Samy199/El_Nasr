# Al Nasr Frontend

Frontend for **Al Nasr Company for Agricultural Crops Packaging** — a bilingual (Arabic/English) B2B website for showcasing Egyptian agricultural products (legumes, seeds, and other crops), with a built-in admin dashboard for managing products, categories, and quote requests. Built with React, Vite, and Tailwind CSS.

## Getting Started

### 1. Install dependencies
```bash
npm install
```

### 2. Set environment variables
Create a `.env` file in the project root (see [Environment Variables](#environment-variables)).

### 3. Run the dev server
```bash
npm run dev
```
The site runs at `http://localhost:5173`. The backend API must be running separately (see the backend README) for any data-driven page to work.

## Design System

All brand colors are defined once as CSS variables in `src/styles/globals.css` and mapped to Tailwind utility classes in `tailwind.config.js` (e.g. `bg-olive`, `text-mint`, `bg-wheat-pale`). Never hardcode a hex value for a color that already has a token — this keeps the whole site themeable from one file.

| Token | Hex | Used for |
|---|---|---|
| `--paper` | `#F7F4EB` | Page background |
| `--ink` | `#173129` | Body text, dark section backgrounds |
| `--olive` | `#173F31` | Primary buttons, headings, sidebar |
| `--mint` | `#278A5B` | Interactive accents, hover states |
| `--mint-pale` | `#D9EFDD` | Badges, positive/success backgrounds |
| `--card` | `#FFFDF7` | Cards, forms, tables |
| `--secondary` | `#E7E8D9` | Secondary/muted surfaces |
| `--muted-foreground` | `#647269` | Helper text |
| `--line` | `#D9D8C8` | Borders |
| `--wheat` / `--wheat-pale` | `#D8B663` / `#F6EDCD` | Warm accents, review-state badges |
| `--clay` | `#B85D42` | Warnings / attention states |

**Fonts:** `Fraunces` (display) + `Inter` (body) for English; `Noto Kufi Arabic` for Arabic, falling back automatically per character via the font stack (no manual font switching needed).

**Note on opacity modifiers:** because colors are defined via `var(--hex)` rather than RGB triplets, Tailwind's `/opacity` modifiers (e.g. `bg-mint/20`) don't reliably apply. For translucent overlays, the raw hex + opacity is used instead (e.g. `bg-[#278A5B]/20`), documented inline wherever it appears.

**Shared hover effect:** `src/features/public-site/utils/leafBurst.js` exports `spawnLeafBurst()` (a one-shot "flying leaves" GSAP animation, contained within an image's bounds) and `ACCENT_THEMES` (a 3-color badge/glow rotation). Both are reused across `CategoryCard`, `ProductCard`, `ProductsShowcase`, and `FacilitySection` rather than duplicated per component.

## Bilingual (EN/AR) Support

- Default language is **English**; the user's choice is persisted in `localStorage` and read on next visit via `i18next-browser-languagedetector`.
- `useLanguageStore` (Zustand) is the single source of truth for the current language and `<html dir>` — components read `currentLang` from it rather than calling `i18next` directly.
- Static UI text goes through `react-i18next` (`t("key")`) and `public/locales/{en,ar}/translation.json`.
- Product/category content is bilingual at the data level (`name_en`/`name_ar`, etc.) — `src/utils/getLocalizedField.js` picks the right field for the active language.
- RTL layout is handled by Tailwind's logical utilities (`ms-`, `me-`, `ps-`, `pe-`, `text-start`, `text-end`) wherever possible, so most components flip automatically with `dir="rtl"` — no per-component RTL branching needed. Icons that need to visually mirror (arrows, chevrons) use the `.icon-directional` class from `src/styles/rtl.css`.
- Some animated components (`HeroSlider`, `ProductsShowcase`) explicitly branch on `isRtl` because their motion direction needs to visually reverse with the reading direction — this is called out in comments where it happens.

## Public Site

| Page | Route | Notes |
|---|---|---|
| Home | `/` | Hero slider, "field to export" journey, category teaser, product teaser (6 latest), latest-products showcase slider |
| Products | `/products` | Full catalog, filterable by category (`?category=<id>` syncs with the URL) |
| Product details | `/products/:slug` | Gallery, specs, quote request form, related products (same category) |
| About | `/about` | Verified Mission/Vision copy from the company brochure, "How We Work," facility photo gallery |
| Contact | `/contact` | Contact details + general quote request form |

`ProductsSection` is shared between the Home page (`limit={6}`, filter UI visible) and the Products page (`limit={null}`, filter controlled via URL) via props (`variant`, `limit`, `activeCategory`/`onCategoryChange`, `excludeId`) rather than being duplicated.

## Admin Dashboard

Routes under `/dashboard/*`, protected by `ProtectedRoute` (redirects to `/dashboard/login` if not authenticated).

- **Overview** (`/dashboard`) — live stats (products, published/draft counts, new quote requests).
- **Products** (`/dashboard/products`) — CRUD, bilingual fields, image upload/removal via Cloudinary.
- **Categories** (`/dashboard/categories`) — CRUD, optional single image per category.
- **Quote Requests** (`/dashboard/quote-requests`) — table with status filters; clicking a row opens a details modal to update status and add an internal note.

## SEO

- `public/robots.txt` and `public/sitemap.xml` (the latter regenerated by `scripts/generate-sitemap.js`, which pulls real published-product slugs from the API).
- `src/components/shared/SEO.jsx` sets `document.title`/meta description per page, and optionally injects page-specific JSON-LD structured data (used for `Product` schema on product detail pages).
- Site-wide `Organization` JSON-LD (verified name, address, phone, logo, Facebook link) is in `index.html`.

### ⚠️ Known SEO gap — Arabic search visibility
The site currently serves both languages from the **same URL** (language is a client-side/`localStorage` preference, not part of the route). This means search engines can only ever index one language version of each page — in practice, English, since that's the default on first crawl. **This is the main blocker to the site appearing in Arabic search results**, and fixing it requires URL-based locale routing (e.g. `/ar/...` vs `/en/...`) with `hreflang` tags — a routing-level change, not a quick patch. See project notes / conversation history for the full discussion before starting this.

## Known Limitations & Next Steps

- **Facility photos** (`FacilitySection.jsx`, shown on the About page) currently render placeholder tiles. Swap the `src: null` entries in `FACILITY_IMAGES` for real image paths once photos are provided — no other code changes needed.
- **Logo files** (`public/logo/logo-en.png`, `public/logo/logo-ar.png`) must be supplied — referenced by `PublicHeader` and `AboutPage` via `src/config/logo.js`.
- **Instagram** is intentionally omitted from `PublicFooter`'s social links — no verified account exists yet. Facebook and WhatsApp links use verified brochure data.
- **Arabic URL-based SEO routing** (see above) is the highest-priority open item for organic Arabic search visibility.
- `ProductDetailsPage`'s "related products" fetch (`ProductsSection` with `excludeId`) requests one extra item to compensate for excluding the current product — acceptable for small catalogs, but worth revisiting if a category ever has very few published products.
